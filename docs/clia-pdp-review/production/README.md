# 검토·승인 화면 (운영) — `/review/`

2026-11-24. 목업 v12(`../mockups/v12/`)를 실제 데이터에 연결한 운영 화면입니다.

## 여는 곳

- **허브 목록:** 태국·싱가포르 법인에서 벌크 업로드 버튼 옆 「검토 / 승인」을 누르면 같은 자리(덮개 화면)에 열립니다.
- **빌더:** 승인 배지(「Not approved」 등)를 누르면 그 제품의 비교 화면이 새 탭으로 열립니다.
- **주소:** `/review/?country=th&lang=th|en|ko`. `&url=<LG.com 주소>`를 붙이면 그 제품의 비교 화면으로 바로 갑니다.

### 오른쪽 = 실제로 내려받는 이미지

제품을 열면 두 채널을 「준비」합니다. 벌크 엑셀(`bulk-jobs.contentFor`)과 같은 순서입니다.

1. 설명 HTML: 빌더 편집본이 있으면 그것, 없으면 `/api/ebay-generate`
2. `/api/v1/slice-html`: 같은 HTML이면 같은 해시이므로, 빌더 이미지 ZIP·이미지형 HTML·벌크 엑셀과 같은 이미지·같은 주소
3. 태국 제품은 `/api/v1/pdp-summary`(Lazada는 HTML, Shopee는 태그 없는 글 + 앞 12장 · 3,000자)
4. lg.com 전체 화면 캡처(`/api/v1/fullshot`)
5. `crawler-py/review_prep.py`: PDP 시작·끝, 이미지마다 lg.com USP 이름

결과는 `crawler-py/out/<slug>/review-<채널>.json`에 두고 버킷에도 올립니다. 처음 준비는 이미지·요약을 새로 만들면 몇 분 걸리고, 이미 만든 것은 다시 쓰므로 금방 끝납니다. 한 번에 2개씩 처리합니다.

**「내용 바뀜」(stale):** 준비한 뒤 다시 크롤했거나, 빌더 편집본을 저장했거나, 요약을 다시 만들었거나, lg.com을 다시 캡처했으면 보이는 것이 예전 내용입니다. 「다시 준비」를 누르기 전에는 승인할 수 없습니다.

### 미리 준비 (2026-11-24)

- **무엇을:** 서버가 Shopee/Lazada 법인(기본 `th,sg`) 제품 가운데 준비 안 됨 · 내용 바뀜 · 실패한 채널을 차례로 미리 준비합니다. 최근 크롤한 제품부터 하고, 10분마다 다시 훑어 새로 크롤했거나 편집본을 저장한 제품을 넣습니다.
- **전부 준비:** lg.com 전체 캡처, Shopee/Lazada 상세 이미지 완성본, PDP 요약까지 미리 만들어 둡니다. 검토 화면에서 누르면 바로 보입니다.
  - `REVIEW_PREWARM_MODE=existing`이면 크롤 데이터와 이미 있는 요약·캡처만 씁니다(AI 요약·Firecrawl 캡처를 새로 만들지 않음). 빈 것은 사람이 그 제품을 열 때 채웁니다.
- **사람 우선:** 사람이 제품을 열면 그 제품이 차례의 맨 앞으로 갑니다. 미리 준비는 한 번에 1개만 돌려서 빌더·벌크 사용자를 느리게 하지 않습니다.
- **설정:**
  - `REVIEW_PREWARM=0`: 끔
  - `REVIEW_PREWARM_COUNTRIES`: 법인 (기본 `th,sg`)
  - `REVIEW_PREWARM_CONC`: 동시에 돌리는 수 (기본 1, 최대 2)
  - `REVIEW_PREWARM_MODE`: `existing`이면 있는 것만으로
- **실패한 것:** 6시간 뒤에 다시 시도합니다.
- **두 채널이 같은 이미지일 때:** 두 번째 채널은 분석(USP · 같은 영역)을 다시 하지 않고 그대로 씁니다.
- **덜 찍힌 lg.com 캡처:** 다음 중 하나면 한 번 다시 캡처합니다.
  - PDP 범위가 상세 이미지의 35%도 안 될 때
  - 상세 이미지 그림을 lg.com에서 25%도 못 찾았는데 PDP 범위가 60%도 안 될 때

  다시 찍어도 같으면 화면에 「lg.com 캡처에 상세 내용이 거의 없음 · 다시 캡처」를 띄우고, 누르면 다시 캡처합니다.
  - 예: TH ISC10E는 지금 lg.com 페이지를 찍어도 요약·스펙과 리뷰만 나옵니다.
- **Firecrawl 캡처:** 아래로 내리는 횟수를 6번에서 24번으로 늘렸습니다. 긴 PDP의 지연 로드 섹션을 찍기 위해서입니다.
- **목록 머리:** 「승인 n/a · 준비 m/a」를 보여 줍니다.

### lg.com 전체 화면 캡처는 크롤할 때 함께 (2026-11-24)

- **Playwright로는 안 됨:** 운영 서버(Railway)의 Playwright는 lg.com(Akamai)에 막힙니다.
  - 운영 DNS 로그: www.lg.com 접속 9초 뒤 Firecrawl로 넘어감
  - 기본 Playwright 시험: 403 「Access Denied」
  - 저장한 페이지 HTML을 Playwright로 다시 그리기: lg.com이 CSS·JS 파일까지 막아(ERR_BLOCKED_BY_ORB) 디자인 없이 글자만 나옴. 상품 이미지만 받아짐
- **그래서:** 크롤(`pdp_pipeline_sl.py`)이 제품 페이지를 받는 그 Firecrawl 요청에 `screenshot@fullPage`를 더해 같은 요청에서 캡처도 받습니다. Firecrawl 호출 수는 그대로입니다. 지연 로드가 찍히게 끝까지 천천히(24번) 내린 뒤 찍습니다.
  - `out/<slug>/lgcom_full.jpg`(폭 960)로 저장하고, 크롤이 끝나면 `crawler-routes.js`가 캡처 저장소(`media-cache/fullshot/<key>.jpg`, 버킷 `media-fullshot/`)에 올립니다.
  - 검토 화면과 빌더 「전체 lg.com 페이지」가 따로 캡처하지 않고 바로 씁니다.
- **이미 크롤한 제품:** 캡처가 없습니다(TH·SG 577개 중 516개). 다시 크롤하거나, 미리 준비·검토 화면이 따로 캡처해야 합니다.

### 승인 규칙

- **체크리스트 승인:** 두 채널 모두 준비가 끝나야 하고, 체크리스트를 끝까지 보고, 「다름」 표시가 없어야 합니다. 같은 이미지 묶음이면 한 채널에서 본 것이 다른 채널에도 봤음으로 남습니다.
- **반려:** 코멘트가 필요합니다.
- **승인 취소:** 상태를 미검토로 돌립니다.
- **목록 「선택 승인」:** 체크리스트 없이 일괄 승인합니다. 확인 창이 뜨고, 기록에는 `via: bulk`로 남습니다.
- **목록 「선택 준비」:** 고른 제품들의 두 채널을 미리 준비합니다.
- **승인 뒤 바뀐 경우:** 다시 크롤하거나 빌더 편집본을 새로 저장하면 승인이 「다시 확인」(stale)으로 바뀌어 승인 전으로 봅니다. 편집본을 지워 승인한 내용으로 돌아가면 다시 승인으로 보입니다.
- **검토자 이름:** 화면 위에 넣은 이름이 그 브라우저에 남고, 승인 기록에 들어갑니다. 로그인으로 확인한 이름은 아닙니다.
- **체크리스트 진행:** 그 브라우저에만 남습니다. 본 이미지 묶음 해시가 같을 때만 이어서 보입니다.

### 같은 영역 스크롤 (자석)

- **기준점 찾기:** 준비할 때 `crawler-py/review_align.py`가 lg.com 캡처와 상세 이미지에서 같은 섹션이 시작하는 자리를 짝지어 기준점을 만듭니다.
  - 오른쪽: 상세 이미지를 만든 HTML을 같은 글꼴·폭으로 다시 그려 섹션(`section.lg-section`) 위치를 잽니다.
  - 왼쪽: 그 섹션의 이미지를 lg.com 캡처 안에서 찾습니다. 크기를 바꿔 가며 정규화 상관으로 찾고, 1/4 축소 후보를 1/2 크기·이미지 전체로 다시 맞춥니다.
  - 이미지 순서가 바뀌지 않는 조합만 씁니다.
- **구간:** PDP 요약(오른쪽에만) → PDP 시작 ↔ 첫 상세 이미지 → 섹션 기준점마다 → 양쪽 끝.
- **스크롤:** 한 구간 안에서는 두 쪽이 같은 속도로 같이 움직이고, 그 구간이 짧은 쪽은 구간 끝에서 「기다리는 중」으로 멈춥니다. 다음 구간은 두 쪽이 같은 자리에서 같이 출발합니다.
- **자석:** 구간 시작마다 스냅 점(`scroll-snap-type: y proximity`)이 있어, 그 근처에서 스크롤을 놓으면 두 쪽의 같은 영역이 맨 위에 맞게 붙습니다. 긴 구간 한가운데서는 붙지 않습니다.
- **표시:** 지금 구간을 양쪽에 초록 테두리와 같은 이름표(번호 · 섹션 제목)로 보여 줍니다. 체크리스트의 지금 항목은 빨강 테두리입니다. 한쪽에 없는 구간(예: PDP 요약)은 「LG.com에 없음 · 기다리는 중」으로 나옵니다.
- **못 찾는 섹션:** lg.com에서 동영상으로 나오는 섹션은 캡처의 장면이 마켓 이미지와 달라서 기준점을 만들지 않고 앞 구간에 합칩니다. 틀린 자리에 맞추는 것보다 낫다고 봤습니다.
- **확인 (TH 3개, 기준점마다 양쪽을 잘라 눈으로 봄):**
  - GC-X257CMEW: 11/11이 같은 영역
  - OLED48C6PSA: 23곳 중 22곳이 같은 내용, 1곳은 같은 섹션의 동영상 자리
  - A9-ACE: 7곳 모두 같은 섹션 (그중 하나는 동영상 장면)
  - 기준점 시트 예: [review-anchors-gc.jpg](./review-anchors-gc.jpg). 왼쪽은 lg.com, 오른쪽은 Shopee 이미지입니다.
- **예전 준비 결과:** 기준점이 없는 예전 준비 결과(판 1)는 「내용 바뀜」으로 보여 다시 준비하게 합니다.

### PDP 범위 (lg.com 캡처, 폭 960px)

- **시작:** 탭 바 아래 빈 띠 뒤 첫 내용 − 16px
- **끝:** 태국어 리뷰 제목 「รีวิวจากผู้ใช้สินค้า」 − 16px. 견본 `crawler-py/review_assets/review-heading-th.png`를 정규화 상관으로 찾습니다.
- **목업 28개로 확인:** 시작 24/28이 목업과 같았습니다. 나머지 4개는 탭 바 바로 아래가 검은 섹션·프로모션 띠라 목업 때도 사람이 고친 제품입니다. 끝은 28/28이 1px 안쪽입니다.
- **못 찾으면:** 캡처 처음·끝을 쓰고 「시작/끝 자동 감지 못 함」 배지를 보입니다. 다른 언어 페이지도 끝 견본이 없어 여기에 해당합니다. 「범위 맞추기」(±10/±100px, 저장 · 자동으로)로 고칩니다.
- **고친 값:** `out/<slug>/review-crop.json`에 저장합니다. 같은 캡처일 때만 씁니다.

## API (`review.js`)

```
GET  /api/v1/review/list?country=th
GET  /api/v1/review/item/:slug?channel=shopee|lazada
POST /api/v1/review/item/:slug/prepare { channel, force?, recapture? }
POST /api/v1/review/item/:slug/crop    { top, bottom, by } | { top: null }
```

함께 바뀐 것:
- `approvals.js`: 편집본 저장 뒤 stale, 기록에 `hashes`
- `server.js`: `POST /api/v1/fullshot`의 `force`(있는 캡처도 다시 찍기 — 새 캡처가 성공해야 바뀜)
- `crawler-py/requirements.txt`: `numpy`. PDP 끝 찾기에 쓰며, Docker 이미지를 다시 빌드하면 설치됩니다.

## 다운로드 잠금

그대로 `APPROVAL_GATE=1`일 때만 잠깁니다(기본 꺼짐). 이 화면이 운영에 생겼으니, 법인 검토 흐름이 자리 잡은 뒤 켜면 됩니다.

## 확인 (로컬 시험 서버, 제품 3개 × 두 채널)

```bash
node review-check.js http://127.0.0.1:3011 .
```

서버에 승인을 기록하므로 운영 주소에서는 돌지 않게 막아 두었습니다.

- **통과한 항목:**
  - 목록 · 갤러리 · BU 필터
  - 같은 영역 스크롤 규칙 어긋남 0(구간마다 시작·30%·끝), 양쪽 이름표 번호 같음, 이미지 비율 어긋남 0
  - 자석: 구간 시작 ±60px에서 휠을 놓으면 10/10 구간 시작에 붙음, 긴 구간 한가운데서는 그대로
  - 체크리스트 전에는 승인 잠김
  - 두 채널 끝까지 스크롤 → 승인 → 서버 기록(검토자 · checklist · 해시)
  - 범위 맞추기 저장 · 자동으로
  - 승인 취소
  - 선택 승인(일괄)
  - 세 언어 사전 키 같음, 버튼·배지 넘침 없음
  - 페이지 오류 0
- **따로 확인한 것:**
  - 승인 뒤 편집본 저장 → 승인·준비 둘 다 stale. 편집본 삭제 → 다시 승인
  - 빌더 배지 → 그 제품 비교 화면
  - 허브 버튼 표시
- **로컬에서 못 한 것:** 로컬에는 AI 키가 없어 A9-ACE의 PDP 요약은 시험용 글입니다(캡처의 「ข้อความทดสอบ」). 다른 두 제품은 「요약을 만들지 못함」 안내가 나옵니다. 운영에서는 벌크와 같은 요약이 들어갑니다.
